**Documentation baseline: 19 October 2026.** This page distinguishes implemented software from confirmed financial acceptance. It is not a live health endpoint.

V37 is installed after authenticated storage capture, preserving financial state and pending operations. It corrects the mixed service's use of a historical birth account after source replacement and adds bounded mobile read recovery. The release passes 491 repository checks, eight focused engine tests and 27 focused mobile tests. The new standalone APK is built. Phone history now shows the ETH, SOL and BTC self-transfers as confirmed; ETH and SOL also have independent chain corroboration. READY and public routing therefore remain separate from financial PAEG/DeFi acceptance.

The default investment also exceeds available operator USDC: Aave has 2 USDC against a one-share preview of 3.096476 USDC, while the Morpho underlying balance is zero. Payments, swaps, settlement and redemptions that could not pass their prerequisites remain **unexecuted**, rather than demonstrated failures. Twenty focused HOST financial tests pass, without establishing public acceptance. The installed diagnostic APK separates share-account observations from failed budget reads and preserves a newly validated connection when its later balance query fails. Prepared server corrections move historical membership and retained-permission validation before the bounded current-state observation, retain fresh proof intake before network preflight, reuse network identity only inside a canonical read scope, check protocol-specific USDC capital before investment review, and retire expired unsent proof intake on authenticated reads. Current-state, canonical-root and separate transfer-authorization checks remain enforced. These server changes are not deployed. The corrected APK observes an exact retained deposit before requesting a full budget snapshot. Its OBSERVE_JOB response timed out after 60 seconds, but an independent protected-state read confirms that the original authority subsequently retired the expired intake: Source7 revision 15 retains the same job as FAILED/EPOCH_REPROOF_REQUIRED, with no noteWork or pending send. This clears the unaccepted-proof blocker without restarting the engine; it does not confirm a deposit or authorize another one. The public saved-operation recovery route also remains unconfirmed. No engine restart or deployment was performed during this audit. The next local robustness pass retains one authenticated membership path per live authority, checks its exact current root, backing and spend state on every read, and refreshes it once after a concurrent insertion. A lost HTTP response is covered through the actual SDK, authority, Vault and an ephemeral HTTP listener: reconnecting obtains a fresh status without repeating unchanged membership discovery. Historical membership is not a cached available balance, and a new process reconstructs it. Fault coverage also checks retained transfer identity, lost-send observation, stale permissions, insufficient protocol-specific capital and unchanged transfer ceilings. These remain local acceptance scopes until the grouped update is deployed and tested on the phone.
