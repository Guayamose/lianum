## Calculation criterion

Each objective is broken down into five requirements that cover its original clauses. Each requirement weighs 20%. The objective note is the average:

`porcentaje = (nota1 + nota2 + nota3 + nota4 + nota5) / 5`

| Nota | Meaning |
| --- | --- |
| 0 | No implementation of the requirement was found. |
| 25 | Partial implementation; a substantial part or connection is missing. |
| 50 | Implemented and connected, without accrediting the full course of the requirement. |
| 75 | Complete operation accredited in a limited area; the remaining scope remains to be covered. |
| 100 | Covered requirement in its original scope. |

The scope of each note is stated in its row. A complete focal test can prove storage or custody, but not a financial settlement. A compilation credits that the app is built, but does not credit seven networks. The connected code pending integration counts as implementation; a rejected attempt does not become an approved path.

These weights are an explicit follow-up convention. They are maintained for the following revisions. The above figures were ranges without this breakdown: your difference cannot be interpreted as an increase measured during a session. Commits and the amount of tests do not add points by themselves.
